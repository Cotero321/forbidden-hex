# 源能祭坛

目标为 Minecraft 1.20.1 / Forge 47.4.10 / Java 17。以 `SourceAltarRules` 为运行时数值表。本系统独立于母神祭坛，不修改低等坩埚的100 tick火焰加热和零源能规则，不新增获取配方或仪式能耗。

## 已确认规则

- 六个专用祭坛方块水平3×2自动成型，无激活材料。未成型不产能，初始源能为0。
- 基础容量100，基础回复每20 tick 1点。
- 环境水平圆形半径64格，垂直±10格。每种方块独立享有其所在行的数量上限。
- 最大容量＝（100＋环境贡献＋龙蛋800＋龙头500）×最高头颅倍率×最高器具倍率＋豁免加成。
- 豁免加成：陈列普通苦力怕心脏每个250，最多4；有效信标每个400，最多4；有充能的重生锚每个200，最多2。不消耗充能。
- 每秒回复＝1×最高灯具倍率×最多4种不同供品倍率。供品不自动消耗。
- 源能及容量内部使用 `long` 半点单位，151.5等数值可无损存档及同步。

## 交互与默认边界

主控按坐标稳定选择；水平朝向仅用于坛面拼接，摆放不要求6块原朝向一致。成型后空手普通右键任意成员打开同一主控界面。潜行右键在被点中的表面放1件陈列物，同类物品可叠至其正常堆叠上限；潜行空手取回该位置陈列。未成型也可放取陈列物。每块拥有自己的物品，拆块只掉落该位置物品一次；源能仅保存在稳定主控，拆除其他成员后暂停并保留主控储能，主控拆除不转移储能。

祭台普通右键放一件有效供品，空手右键取回。仅选水平8格、垂直±2格内最近4座，距离相同时按坐标稳定选择。重复物品按物品ID仅生效一次，超出4座不参与。它们不占主坛陈列位置。

普通环境方块仅在世界中计数。主坛陈列物识别心脏、圣杯、贤者之石、匕首，以及头颅、灯具、龙蛋/龙头；环境与陈列的唯一增益不会重复叠加。匕首使检测及供能垂直范围变为±14，不叠加。活跃信标要求金字塔等级大于0且无遮挡，重生锚只要求充能大于0。

## 扫描、持久化与无线供能

只在服务端线程读取世界，不加载区块。放置成型时分步扫描一次；存档/区块重载或结构重新成型时重建基线。取消100 tick周期全域重扫，随后监听方块成功写入、祭台/陈列物修改、信标激活翻转与区块加载/卸载。放置、破坏、爆炸、活塞、生长和命令经 `LevelChunk.setBlockState` 的变化均只更新相关位置；同位置事件合并并读取最终状态。直接绕过区块setter修改内部区段的第三方实现不在监听保证范围内。

每维度每tick共享8192位置预算，首次扫描、增量更新、卸载贡献移除和新加载区块补扫均按祭坛轮转推进；新加载时只补扫对应区块。缓存仅保存有贡献的位置和未封顶计数，容量计算时再封顶，删除超额方块不会误减；头颅、灯具与祭台保留全部候选，删除最高项能回退。内外高度分桶预读至±14，未放匕首时仅采用±10，放取匕首无需重新全域扫描。缓存内存随有效位置数量增加，不为所有空气/无关方块建立记录。

初始化和事件落地完成后才采用快照，菜单显示扫描状态；尚有未处理变化时暂停供能，避免使用已拆除增益。结构不完整立即暂停；存档恢复在首轮完成前保留已存源能，避免临时基础容量将其错误截断。无需变化时不产生扫描工作。

无线调用方使用 `SourceEnergyNetwork.request(ServerLevel, BlockPos, long halfUnits, boolean simulate)`；需求必须为正数，同维度且完整成型，选范围内最近且足额的单个主控。整笔成功或失败，模拟不扣费，不拼凑多个祭坛，不透支，不修改现有设备消费规则。

源能、回复计时和陈列物存入NBT；非法储能/堆叠数量限制到合法范围，未知物品按原版空物品处理。索引在卸载时清理，不跨存档持有世界。界面long值用4个16位槽完整同步。
